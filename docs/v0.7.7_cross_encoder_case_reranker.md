# V0.7.7 Cross-Encoder Case Reranker

本阶段在冻结 V0.7.6 Hybrid Top3 上增加 `BAAI/bge-reranker-base` Cross-Encoder。候选深度固定为 3，因为 V0.7.6 frozen Hybrid Recall@3=1.0000；不会依据 reranker 结果在 Top3/5/10 之间调参。

Case text 只包含标题、关键词、基本案情、争议焦点、裁判要旨和长度受控的裁判理由。`source_url`、`source_file`、`case_id` 等 provenance 不进入模型相关性文本，但会保留在结果中。

验证使用 12 条在任何 reranker 输出产生前冻结的新 blind validation queries（easy 3 / medium 5 / hard 4），并保存 SHA-256。V0.7.6 held-out Test 已被用于前一阶段评估，不能重新描述为 V0.7.7 的独立测试。旧 30-query 结果仅作 Full-30 descriptive comparison。

模型不可用时，`reranked` mode 返回原始 Hybrid Top3，并暴露 unavailable 状态；BM25、Semantic、Hybrid 和默认模式不受影响。最终是否推荐 reranked 作为默认路径，依据 blind validation 的收益、错误破坏和 CPU latency 决定。

详细结果见 `evaluation/v077_reranker_results.json`、`evaluation/v077_reranker_metrics.json` 和 summary。

## 本次验证结果

12-query blind validation：Hybrid Recall@1/MRR/nDCG@3 = 1.0000/1.0000/1.0000；Reranked = 0.9167/0.9583/0.9626。fixed=0，broken=1，unchanged=11，net Top1 gain=-1。Cross-Encoder 平均 rerank latency 约 741 ms，model load/warm-up 约 1.87 s。

Full-30 仍为 descriptive：Hybrid Recall@1/Recall@3/Recall@5/MRR = 0.9667/1.0000/1.0000/0.9833；Hybrid+Reranker = 0.9667/1.0000/1.0000/0.9833。该结果不能替代新的独立测试集。

因此当前推荐并已落实：`DEFAULT_CASE_SEARCH = hybrid`。CLI 未显式传入 `--mode` 和 `UnifiedCaseSearchService.search()` 未显式传入 `mode` 时均使用 Hybrid；`bm25`、`semantic`、`reranked` 仍可显式选择。Reranked 不作为默认路径，模型不可用时安全返回 Hybrid Top3，并报告 unavailable 状态。选择 Hybrid 的原因是 blind validation 中 Hybrid 为 1.0000 Recall@1，而 reranker 出现 1 条 broken query、0 条 fixed query，且 CPU 延迟约高两个数量级。
