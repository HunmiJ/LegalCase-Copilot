# V1.5.2 Citation Failure Analysis

## 根因

已确认的根因是法规-only 主 pipeline 的 citation namespace 不一致：

- `build_context(reranked, context_top_k)` 的兼容位置参数路径生成 `[1]`、`[2]`。
- generator prompt 要求真实 context 中的 `LAW-1`、`LAW-2`。
- validator 只接受当前 context 中存在的 citation，因此 `LAW-1` 在法规-only context 中被拒绝为 `unsupported citation`。
- 案例增强路径使用命名参数，生成 `LAW-*` 与 `CASE-*`，与 prompt 一致，因此成功率明显更高。

这不是通过放宽 validator 解决的问题，而是修正主 RAG 路径生成 context 的方式。

## Citation 格式链路

| 层 | 实际规则 |
|---|---|
| 法规-only 旧兼容调用 | `[1]`、`[2]` |
| 修复后的主 pipeline | `LAW-1`、`LAW-2`，展示为 `[LAW-1]` |
| 案例增强 context | `LAW-1`、`CASE-1`，展示为 `[LAW-1]`、`[CASE-1]` |
| Prompt | 只能引用当前 context 明确列出的 `LAW-*` / `CASE-*` |
| Parser | 安全支持 `LAW-1`、`[LAW-1]`、`CASE-1`、`[CASE-1]`；旧数字保留为 `[1]` |
| Validator | 必须在当前 context 精确找到 citation；不存在的 ID 始终拒绝 |

## 最小安全修复

- 主 pipeline 的法规-only路径改为使用 `build_context(law_items=..., case_items=[])`，因此真实生成 context 使用 `LAW-*`。
- 保留 `build_context` 的旧位置参数行为，避免破坏历史调用者。
- 规范化仅移除合法 namespace 外层方括号；不把数字、相近编号或不存在的 ID映射到真实 citation。
- 强化 prompt，明确不得把条号、排序号或自行推测数字转换成 citation ID。

## 回归结果

新增 namespace 测试覆盖合法 LAW、合法 CASE、方括号规范化、不存在 LAW、不存在 CASE，以及 law-only 不依赖 CASE namespace。

`pytest`：154 passed，1 warning。

5条真实 smoke test 未通过，原因仍为 `URLError / WinError 10013`，因此没有启动完整30条重评测，也没有伪造修复后的真实指标。完整30条评测应在网络权限恢复后重新运行。
